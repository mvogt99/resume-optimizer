## Project Overview

ATS-friendly resume optimization web app. Flask backend + React 18 SPA. Users upload resumes, paste job descriptions, and receive optimized resumes with ATS scores, keyword analysis, journey mining, LinkedIn campaigns, and agentic career assistance.

Generated by RTX 5090 (Qwen3-Coder-30B) + Claude Sonnet 4.5 via Digital Twin API (Feb 2026).

## Architecture

**Flask backend → SQLite/PostgreSQL + ArangoDB (graph) + Qdrant (vector)**

### Application Factory

`backend/app.py` uses `create_app(testing=False)`. All routes are Blueprints registered inside the factory. `cloudlift_db_adapter.resolve_database_url()` is called before any blueprint import so `DATABASE_URL` is set before `models.init_db()` runs.

### Database Layer

**SQLite / PostgreSQL** (`backend/models.py`, `backend/db_engine.py`):
- `db_engine.py` detects `DATABASE_URL` and provides a Postgres cursor wrapper that translates `?` → `%s` placeholders and populates `lastrowid` via `RETURNING id`.
- Schema split: `models_schema1.py` (core tables), `models_schema2.py` (extended tables), `models_journey.py` (journey/campaigns). `db_pg_init.py` holds PostgreSQL DDL equivalents.
- Model classes (User, Resume, etc.) live in `models_classes.py`, re-exported from `models.py`.
- Always run `python app.py` from `backend/` — `database.db` is created relative to CWD.

**ArangoDB** (`backend/arango_client.py`, `backend/arango_client_domain.py`):
- 16 `ro_`-prefixed collections + named graph `ro_knowledge_graph`. SHA-1 deterministic keys.

### Authentication

`backend/auth.py` implements JWT. Routes use `@require_auth` which accepts:
1. `Authorization: Bearer <token>` (primary)
2. Legacy `user-id: <int>` header (fallback, no role enforcement)

`@require_admin` requires `role == "admin"`. Sets `g.user_id` (int) and `g.user_role`. Users have `status` (`pending`/`active`) and `role` (`user`/`admin`).

### LLM Routing

**`smart_llm.py`** — local RTX 5090:
- Calls gateway model selection (`/api/models/select`) to pick the best local model, triggers a swap if needed, then calls port 8021 directly. Falls back to `Qwen/Qwen2.5-Coder-32B-Instruct-AWQ`.

**`cloudlift_llm_adapter.py`** — cloud path:
- When `CLOUDLIFT_ENV=aws`, calls AWS Bedrock (Claude Haiku/Sonnet). Zero cloud imports in local mode.

Most feature code calls `smart_llm.call_llm(prompt, task_type)`. FTAL harness is also callable directly via `llm_helper.py` (6000-char chunks, 3-tier JSON extraction).

### CloudLift Adapters

`backend/cloudlift_*.py` provide cloud-vs-local abstraction:
- `cloudlift_db_adapter.py` — resolves RDS credentials from Secrets Manager when `CLOUDLIFT_ENV=aws`
- `cloudlift_graph_adapter.py` — ArangoDB vs. Neptune
- `cloudlift_vector_adapter.py` — Qdrant vs. OpenSearch
- `cloudlift_queue_adapter.py` — Artemis STOMP vs. SQS
- `cloudlift_llm_adapter.py` — RTX 5090 vs. Bedrock

### PersonaForge Integration

`backend/personaforge_client.py` — non-blocking: `pf_recall`, `pf_remember`, `pf_feedback`. All calls silently catch connection errors. Requires PersonaForge at `PF_URL` (port 8090). Tests mock it by default; `@pytest.mark.real_pf` bypasses the mock.

### Routes

All routes are Flask Blueprints. Agents routes are split across `backend/agents_routes*.py`:

| Blueprint | Purpose |
|-----------|---------|
| `auth_bp` | Register, login, password reset |
| `resume_bp` | Upload, optimize, score, versions |
| `keyword_bp` | Group, equivalency interview/rewrite/match, ignore list |
| `experience_bp` | Conversational extraction (6-stage state machine) |
| `journey_bp` | Journey mining, timeline, skills, narratives |
| `campaigns_bp` | Campaign CRUD, posts, analytics |
| `projects_bp` | Client project analysis + ArangoDB approval |
| `builder_bp` | Resume builder interview |
| `alignment_bp` | Resume–JD alignment analysis |
| `chat_bp` | ATS improvement chat |
| `agents_bp` | Job Scout, App Tracker, Career Advisor, Cover Letter, Interview Coach, Resume Tailor |
| `admin_bp` | User management (admin-only) |
| `health_bp` | `/api/health` liveness probe |

### Background Jobs

`backend/batch_jobs.py` — daemon threads + `batch_jobs` SQLite table. Journey mining, project analysis, post generation, and agent searches all use this. Poll via `/api/jobs/<id>/status`.

### Frontend

React 18 + React Router 6 + Axios. `Dashboard.jsx` is the main SPA shell with tab-based navigation. `frontend/src/services/api.jsx` sends `Authorization: Bearer <token>` from localStorage and reads `REACT_APP_API_URL` (defaults to `http://localhost:5000/api`).

### User Profile Data (`working-docs/linkedin/`)

Use `linkedin_profile_merged_api_preferred.json` as the canonical source — most complete, structured fields. Contains full name, headline, 4 prior roles with KEY ACCOMPLISHMENTS bullets, 70+ skills with endorsement counts, 9 recommendations.

## RTX 5090 Delegation: Conceptual Teaching (MANDATORY)

When delegating tasks to RTX 5090 (via FTAL harness, delegate_task MCP, or direct curl to port 8021), **always use conceptual teaching** in the prompt. Never provide exact code or exact expected values — teach the model HOW to approach the problem.

**Provide:**
- Behavior descriptions ("this function parses PDF, extracts text, returns dict with sections")
- API contract shapes ("returns `{ score: float, keywords: string[], missing: string[] }`")
- Quality criteria ("each test needs >=2 assertions, validate types AND values")
- Pattern guidance ("use Flask test client, create user first, then upload resume")
- Anti-pattern warnings ("don't mock the database — use real SQLite test fixtures")

**Do NOT provide:**
- Exact code to copy-paste
- Exact expected values (e.g., "assert score == 0.85")
- Line-by-line implementation

**Effectiveness:** HIGH for backend/API tests, schema validation, pure logic. MEDIUM for integration tests. LOW for React component tests (requires DOM knowledge the model can't infer).

## Key Gotchas

- **Schema init order:** `cloudlift_db_adapter.resolve_database_url()` must run before any blueprint import because blueprints transitively import `models`, which calls `init_db()` on import.
- **Placeholder substitution:** `db_engine.py`'s `_PgCursorWrapper` auto-translates `?` → `%s`. Never use `%s` in SQLite-targeted SQL.
- **Models split:** `models.py` is the entry point; classes are in `models_classes.py`; DDL is in `models_schema1.py`, `models_schema2.py`, `models_journey.py` (SQLite) and `db_pg_init.py` (PostgreSQL).
- **SQLite created in CWD:** `models.py` creates `database.db` relative to CWD — always run `python app.py` from `backend/`.
- **Journey workdir:** `JOURNEY_WORKDIR` env var controls what `journey_miner.py` scans. Tests set this to a temp dir via conftest to avoid scanning the real workdir.
- **NLP model required:** spaCy `en_core_web_sm` must be downloaded separately or `nlp_engine.py` will fail silently (`nlp=None`).
- **Google Drive requires OAuth:** `gdrive_service.py` needs OAuth token at `~/.config/resume-optimizer/token.json`.
- **LinkedIn dual cache:** `_cached_linkedin_profile` has skills as strings (for resume text), `_cached_linkedin_raw` has dicts with endorsement counts (for skills_optimizer).
- **Equivalency reclassification order:** In `resume_scorer.py`, equivalency reclassification MUST happen before `raw_score` calculation — otherwise `keyword_coverage` (20% weight) is blind to equivalencies. `SCORE_FLOOR = 15`.
- **Section header preservation:** LLM rewrites in `keyword_equivalency.py` lose section headers from `proposed_text`. `_preserve_section_headers()` post-processing re-prepends them.
- **Employer group detection:** `_is_employer_group()` in `keyword_grouper.py` marks groups `employer_group: true`. These must be excluded from `totalMissing` and the equivalency panel.
- **Dispute auto-save:** If `covered=true` and `confidence >= 0.75`, the equivalency is auto-saved without user interaction.
