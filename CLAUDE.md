# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

ATS-friendly resume optimization web app. Flask backend (NLP keyword extraction via spaCy/NLTK) + React 18 SPA frontend. Users upload resumes, paste job descriptions, and get optimized resumes with ATS compatibility scores.

Generated by RTX 5090 (Qwen3-Coder-30B) + Claude Sonnet 4.5 via Digital Twin API (Feb 2026).

**Database:** SQLite (`backend/database.db`), auto-created on first import of `models.py`. Tables: `users`, `resumes`, `job_descriptions`, `resume_versions`, `experience_sessions`, `experience_messages`, `extracted_experiences`, `batch_jobs`, `client_projects`, `project_documents`, `journey_sources`, `journey_events`, `journey_narratives`, `campaign_sessions`, `campaign_messages`, `campaigns`, `campaign_posts`, `alignment_analyses`, `rewrite_suggestions_log`, `keyword_ignores`, `resume_interview_sessions`, `resume_interview_messages`.

## RTX 5090 Delegation: Conceptual Teaching (MANDATORY)

When delegating tasks to RTX 5090 (via FTAL harness, delegate_task MCP, or direct curl to port 8021), **always use conceptual teaching** in the prompt. Never provide exact code or exact expected values — teach the model HOW to approach the problem.

**Provide:**
- Behavior descriptions ("this function parses PDF, extracts text, returns dict with sections")
- API contract shapes ("returns `{ score: float, keywords: string[], missing: string[] }`")
- Quality criteria ("each test needs >=2 assertions, validate types AND values")
- Pattern guidance ("use Flask test client, create user first, then upload resume")
- Anti-pattern warnings ("don't mock the database — use real SQLite test fixtures")

**Do NOT provide:**
- Exact code to copy-paste
- Exact expected values (e.g., "assert score == 0.85")
- Line-by-line implementation

**Effectiveness:** HIGH for backend/API tests, schema validation, pure logic. MEDIUM for integration tests. LOW for React component tests (requires DOM knowledge the model can't infer).

## Key Gotchas

- **NLP model required:** spaCy `en_core_web_sm` must be downloaded separately or `nlp_engine.py` will print an error and the `nlp` variable won't be defined
- **SQLite created in CWD:** `models.py` creates `database.db` relative to wherever `python app.py` is run from — always run from `backend/`
- **Google Drive requires OAuth:** `gdrive_service.py` needs `google-api-python-client` installed and OAuth token at `~/.config/resume-optimizer/token.json`
- **Experience chat LLM calls:** `experience_chat.py` calls FTAL harness at `http://localhost:8000/api/harness/run` — falls back to template questions if unavailable
- **LinkedIn dual cache:** `_cached_linkedin_profile` has skills as strings (for resume text), `_cached_linkedin_raw` has dicts with endorsement counts (for skills_optimizer). Both set on startup and via `/api/import/linkedin`
- **Equivalency reclassification order:** In `resume_scorer.py`, equivalency reclassification MUST happen before `raw_score` calculation — otherwise `keyword_coverage` (20% weight) is blind to equivalencies. `SCORE_FLOOR = 15` (was 20).
- **Section header preservation:** LLM drops section headers from `proposed_text` in rewrites. `_preserve_section_headers()` in `keyword_equivalency.py` post-processing re-prepends them — prevents section completeness regression.
- **Employer group detection:** `_is_employer_group()` in `keyword_grouper.py` sets `employer_group: true` on groups. These must not be counted in `totalMissing` or passed to the equivalency panel.
- **Keyword ignore list:** `keyword_ignores` table. `group_keywords_endpoint` AND `score_text_endpoint` both load and apply it — ignored keywords are excluded from grouping AND from scoring.
- **Dispute auto-save:** If dispute returns `covered=true` and `confidence >= 0.75`, the equivalency is auto-saved without user interaction.
