RISK 1 — GCP is a secondary platform, not primary depth (HIGH, certain interview question)
   Mike's primary cloud platform is Azure. AWS is secondary. GCP is tertiary — deployed
   as part of PwC's multi-cloud CDM extension, but not the primary delivery platform for
   any major solo engagement. Quantiphi is a GCP Premier Partner; every engagement will

   Suggested interview framing:
   "My primary cloud platform is Azure, with AWS as secondary and GCP as the third leg
   of a multi-cloud architecture I built at PwC. I understand the GCP data platform deeply
   at the architectural level — BigQuery, Dataflow, Pub/Sub, Dataplex, Vertex AI — and
   have deployed these services as part of a production multi-cloud canonical metadata model.
   My Azure depth is directly transferable: every pattern in BigQuery has an Azure/Databricks
   equivalent I've run in production. The GCP-specific tooling ramp for someone with this
   architecture foundation is a matter of weeks, not months. I'd also note that Codeaira —
   which I've built the equivalent of operationally — is a GCP-native tool I understand
   from first principles, not just documentation."

RISK 2 — Vertex AI hands-on depth (MEDIUM)
   Quantiphi works extensively with Vertex AI for MLOps, model serving, and feature stores.
   Mike has equivalent Azure ML / vLLM / MLflow patterns but has not personally deployed a
   Vertex AI Pipeline or trained a model using Vertex AI infrastructure. The resume is
   honest: "architectural equivalence mapped" and "GCP-native MLOps trajectory underway."

   Suggested interview answer:
   "My MLOps foundation is in Azure ML and vLLM-based inference, which maps directly to
   Vertex AI Pipelines and Vertex AI Model Monitoring. I've designed feature stores at the
   architectural level and governed the data infrastructure that feeds them. The Vertex AI
   specifics — API surfaces, pipeline YAML definitions, Feature Store configuration — are
   a short ramp from deep Azure ML experience. I've been actively closing that gap."

RISK 3 — Fortune 100 vs. Fortune 500 client scale (LOW)
   Quantiphi says "Fortune 100 enterprises." PwC clients are Fortune 500 / Global enterprise
   scale. The distinction matters for some technical interviewers — Fortune 100 implies
   extreme data volumes, regulatory complexity, and organizational complexity that not all
   Fortune 500 engagements reach. PwC and AHEAD healthcare clients are genuine enterprise
   scale, but "Fortune 100" is aspirational.

   Suggested interview answer:
   "PwC's data platform engagements were at the Fortune 500 / Global 1000 level — $5M+
   program budgets, 50+ person delivery organizations, multi-cloud architectures governing
   billions of records. The technical complexity and organizational scale are directly in
   the Fortune 100 range."

RISK 4 — Looker / Dataplex depth (LOW)
   Quantiphi is a Looker and Dataplex partner. Mike has Power BI and Purview as primary
   BI/governance tools. Looker and Dataplex are listed in Technical Skills as GCP-native
   equivalents but without hands-on project depth.

   Suggested interview answer:
   "Power BI and Azure Purview are my primary tools at depth. Looker is the GCP semantic
   model layer — the patterns (LookML semantic models, governed metrics, access controls)
   map directly to Power BI Premium semantic modeling concepts. Dataplex is the GCP
   equivalent of Azure Purview for catalog, lineage, and data quality. I'd be productive
   in both within a sprint."

RISK 5 — Specific AI-enabled use cases: fraud detection, customer personalization (LOW)
   JD names "customer personalization, fraud detection, forecasting, intelligent automation"
   as target AI use cases. Mike has forecasting and anomaly detection through ML at SPR,
   and intelligent automation through agentic AI, but not explicit fraud detection or
   personalization project experience. These are illustrative examples in the JD, not hard
   requirements.
