SKILL 5: Integration Testing

Approach and Tooling
The core approach is TDD with expectation requirements validation built directly into the data platforms. More recently, I've added a validator component service to the architecture. This service tests new pipelines and capabilities before they enter the CI/CD pipeline and its associated test suites. The goal is to catch configuration errors and design issues early, before they're embedded in the deployment process.
How Configuration-Driven Changes Testing
In traditional coded pipelines, integration testing is about exercising code paths and catching logic errors. In a configuration-driven architecture, testing shifts toward validating that configurations produce expected outputs and that the abstraction layer is working correctly. The configurations themselves become the specification — and the tests validate that the specification is being honored.

 State Machine Design (resume_interview.py)

 - Linear progression: welcome → contact → objective → experience → education → skills →
 optional → review
 - Experience loop: sub-stages exp_title→exp_employer→exp_dates→exp_duties→exp_more?. On
 "yes more" → increment experience_index, loop to exp_title. On "no" → advance to
 education.
 - Education loop: same pattern, simpler (degree→school→year→more?)
 - LLM + template fallback: each stage has hardcoded template questions (plain language,
 non-tech examples). LLM generates contextual follow-ups when available.
 - Data extraction: parse user responses into context_json fields. LLM for fuzzy
 extraction, regex fallback for structured data (dates, emails, phones).
 - Stage advancement: automatic when required fields populated. Explicit "next" for
 optional stage.

 Template Question Examples

 - Welcome: "Hi! I'm going to help you build your resume step by step. Let's start with
 your name — what's your full name as you'd like it to appear on your resume?"
 - Experience duties: "What were your main responsibilities at {employer}? Try to list 3-5
 things you did regularly. For example, a teacher might say: 'Taught math to 30 students,
 created lesson plans, led parent conferences.'"
 - Skills: "What skills would you highlight? Think about both technical skills (like
 software you use) and people skills (like communication or teamwork). Any certifications
 or licenses?"

 Resume Compiler Design (resume_interview_compiler.py)

 - Auto-template selection: maps career_field keywords → template type

 - Bullet enhancement: LLM rewrites raw duties with action verbs + quantification
 - Output: plain text matching parsed_text format in resume_versions
